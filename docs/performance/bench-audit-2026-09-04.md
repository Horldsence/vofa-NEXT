# 波形数据链路性能审计

## 结论口径

这是软件各处理环节的分层基准与后端并发压测，**不是整桌面端到端认证**。
不以纯解析吞吐推断 GUI 流畅度，不以队列丢弃维持的摄入速度宣称全量计算达标。
14 MB/s = 700,000 帧/s × (4 通道 × 4 B + 4 B 帧尾)，MB 使用十进制；
Criterion 的 MiB/s 使用二进制，两者不混用。

环境：Apple M4，10 逻辑核，16 GiB 内存，aarch64 macOS 27.0（26A5425a）；Rust 1.96.0
（LLVM 22.1.2），Node 26.7.0，pnpm 11.22.0。Rust 基准使用 optimized bench
profile，脚本用 `CARGO_PROFILE_BENCH_DEBUG=0` 固定符号开销，不改用户的 Release
调试配置；JS 基准使用 Vitest/Node，不等价于 Safari WebView。

微基准与首轮长跑基线：`93e2770` 加屏障测试 lint 修正与基准脚本参数；后续队列
预算复测单独列出，不能混作同一版本。保留用户的依赖
升级、Tauri capability 与 updater 配置。11 时与 18 时的实测性能有明显系统性差异，
不能把 Criterion 自动显示的跨时段 change 百分比当成代码优化收益。

## 可复现入口

```bash
bash scripts/bench-audit.sh quick  # 每个长跑场景 60 秒
bash scripts/bench-audit.sh full   # 每个长跑场景 300 秒
```

按顺序运行以避免相互争抢 CPU。脚本保留编译日志、Criterion 文本、长跑 JSONL
和前端 JSON 到 `src-tauri/target/bench-audit/<时间>/`。Criterion 完整统计在
`src-tauri/target/criterion/`。生成物不提交。
构建失败立即停止；独立测量失败仍继续采集其他场景，末尾统一非零退出。
该续跑逻辑通过注入退出码 7 再执行成功场景验证；没有因此重跑全部微基准。

单独控制长跑：

```bash
cd src-tauri
CARGO_PROFILE_BENCH_DEBUG=0 VOFA_SOAK_SECONDS=300 VOFA_SOAK_GRAPH=math VOFA_SOAK_GENERATOR=1 \
  cargo bench -p data_plane --bench pipeline_soak
```

`VOFA_SOAK_GRAPH=raw` 使用直接波形，`math` 使用四条 Add → 波形 CH 输入；
`VOFA_SOAK_GENERATOR=1` 使用真实 TestData 定时器和广播；`0` 使用固定
70 KB/5ms 输入。无输入参数时默认 60 秒、raw、固定输入。
`VOFA_SOAK_EVAL_STALL_MS=100` 可另外模拟图锁约每 5 秒占用 100ms，验证短时积压；
默认关闭，不混入正常长跑。审计脚本额外执行 30 秒该场景，长跑结果仍须零丢弃。
`VOFA_SOAK_EVAL_WORKERS=3` 显式设置评估线程数（不等同于解析线程上限），
启动时打印采样率、完整 pipeline 配置及人为停顿参数，便于复核实际工作负载。
`VOFA_SOAK_INGEST_STALL_MS=500` 约每 5 秒暂停一次摄入、生成器继续运行，检验恢复后
积压补交的承载；脚本另外执行 30 秒该场景。人为停顿分别运行，不混入正常长跑。

## 覆盖矩阵

| 环节 | 工作负载 | 指标与限制 |
|---|---|---|
| 原始记录与金字塔 | 4 通道，滚动环，多层级联 | 单批耗时、按 20 B/帧折算的吞吐 |
| 原始窗口 | 320 万点历史、概览 2000 点、主图 12000 点 | 查询耗时；历史点数不是实际扫描量，不能换算处理点数/s |
| 派生查询 | 4 条派生，历史容量 2k/100k/1750k，最近 128 点 | 容量增长是否导致耗时退化 |
| 字节摄入 | 4 通道 JustFloat，64 KB 批 | 解码/时钟/记录/入队；无复杂图、不含 IPC |
| 图计算 | 单链、8 路、8×6 深链、4 路 Filter，1/2/4 worker、SIMD | 10k 帧耗时；保持跨轮单调时间，不含波形 sink |
| 图编译 | 同上 4 种图 + 字节链 Transport→Protocol→ProtocolSource→Math | 全链与 HIR/值平面/字节平面/lowering 分段耗时；前端拓扑改动触发路径 |
| 槽位求值 | 单链、8×6 深链、4 路 Filter，10k 帧批 | `CompiledEval::run` + 每帧清零协议；与 graph_eval 端到端差值为数据平面开销 |
| 边集合 | 8/64/512 条边增删、索引重建、帧路由、环检测 | buffer_graph 数据结构本身；不含字节平面路由 |
| 触发器匹配 | 6 种匹配类型 × 1/8 规则 × 命中/未命中 | `TriggerMatcher::match_input` 单次调用；含每次调用克隆规则表的开销 |
| 帧解码 | 帧头+N×UInt16LE[+Sum8 校验]+帧尾，2048 帧连续流 | `FrameParser::feed` 字节吞吐；通用逐帧状态机，不等同专用 JustFloat 解码 |
| 图提交辅助 | 50/500 节点派生端口表、ProtocolSource 注入 | `compute_derived` / `inject_protocol_sources` 纯函数；不含编译与 AppState 写入 |
| 波形编码 | 4ch×2k、4ch×12k、16ch×12k | WWB1/JSON 编码耗时与实际字节量，不含 IPC |
| CPU/GPU 包络 | 100k/1M/4M 点，2048 列 | 含 GPU 上传/读回；无适配器必须明确标为未测 |
| 前端 CPU | 同三种窗口规模 | WWB1 解码、JSON 归一化、全通道 AC+测量；不含 React/Canvas |
| 并发长跑 | 14MB/s、4ch、原始字节保留、异步求值、样本订阅、30Hz 主图+概览 | 实测接收、帧计数、P50/P95/P99/max、队列峰值、丢弃、排空时间 |

长跑原始时间必须单调，所有通道列长度必须与公共时间轴一致，JustFloat 输入
字节数必须等于帧数 × 20。当前版本还断言实收 >10 MB/s、接收/求值/DataBus 摄入/
预览零丢弃；退出成功不代表 GUI 流畅或所有延迟符合要求，延迟仍须检查 JSON。

## 定位与改动

- **并行屏障永久自旋**：完整图基准在 `eight_paths_w4_simdtrue` 预热卡住超过
  3 分钟，采样时 CPU 约 298%，主线程与三个 worker 都在屏障 yield。
  `SpinBarrier` 先增加到达计数再读取世代，可能漏掉最后到达线程的放行，
  永久等待下一个世代。改为先读取世代再报到；增加四线程 20,000 轮回归。
  同时让协调者/worker 的 panic 释放等待者，并保留原始 panic 传播。
  原始采样记录位于本机 `/private/tmp/vofa-eval-bench-sample.txt`。

- **派生查询历史扫描**：固定最近 128 点请求，从历史起点逐点推进。
  2k/100k/1750k 容量的基线分别为 21.95µs / 814.91µs / 14.009ms。
  改为向前指数搜索 + 二分；连续点仍常数推进、重复时间戳仍逐个消费。
  同机对比为 8.56µs / 8.81µs / 9.28µs，最大容量减少约 99.934%。
  基线名为 `linear_scan`，不是对整软件性能的改进百分比。
- **图求值占用原始缓冲锁**：求值改持有独立派生写句柄；原始锁只用于取句柄，
  不跨整批图计算。派生样本按批写入，结构世代校验阻止清空后旧索引写入新序列。
  回归覆盖锁竞争、清空、深拷贝冻结与串行/并行/SIMD 等价性。
- **无消费者的历史写放大**：只持久化 Waveform `CH<n>` 派生输入，不记录
  Math 中间边或只读最新值的仪表边。标准 ProtocolSource `ch<n>` 使用已有原始列。
  纯 ProtocolSource→Sink 图只评估批尾；含计算或有状态节点仍逐帧评估。
- **压测源限速**：0.5ms 节拍受毫秒级定时器及每次迟到重新定相影响，旧生成器
  700k×4 在 15 秒基准中实收仅 4.171MB/s。消息改为约 5ms 并保留截止相位；
  暂停期间不补账，每轮检查取消。消息仍固定帧数，Lagged 换算共享同一规则。
- **指标失真**：异步 ingest 与 eval 不再相减、不共用批数分母；产帧只计实际
  摄入，eval 耗时包含真实锁等待。报告使用实际间隔，累计诊断不随日志清零。
  停止日志分别打印广播消息数与评估帧数，不再相加为“条”。
- **内存估计**：补计原始金字塔的已分配容量；该值仍不包含整个进程、分配器、
  GPU、前端和队列，不能替代 RSS。
- **基准质量**：图基准每轮推进时间戳；等价测试连接真实 CH 输入；自适应控制器
  测试注入单一观察时刻，不再把实际调度误差当成固定 10ms。

## 实测结果

原始记录：`src-tauri/target/bench-audit/20260904-180606/`。以下微基准使用
Criterion 点估计，长跑使用单次调用的实际分位数；两者不能互作尾延迟。
共 44 个微基准场景（含本机权限下复核的 3 个 GPU 场景）。首次脚本全部测量结束后，
末尾中文输出紧邻变量名触发 Bash `unbound variable`；已改为花括号限定变量，
测量文件未丢失。JSON 编码吞吐也已改为按 JSON 实际输出字节计数并重跑。

| 块组合 | 帧长 | 耗时 | 吞吐 |
|---|---:|---:|---:|

`FrameParser` 是逐帧状态机，吞吐 (~21MB/s 十进制) 与专用 JustFloat 摄入

为 2.70/23.7µs（约 47ns/节点），`inject_protocol_sources` 0.37–0.50µs，
均可忽略，bench 用于防止回归。

沿用本节开头口径。

### 编码与前端 CPU

编码采用最后重跑的 `waveform-wire-final.log`；前端采用 `frontend.json`。
编码与前端数据夹具不同，下面不能相加作为端到端传输延迟。

| 窗口 | WWB1 / JSON 字节 | Rust WWB1 / JSON 编码 | JS WWB1 解码 / JSON 解析归一化 | 全通道 AC+测量 |
|---|---:|---:|---:|---:|
| 4ch × 2000 | 48,080 / 97,626 | 5.30 / 163.22µs | 0.39µs / 0.284ms | 0.162ms |
| 4ch × 12000 | 288,080 / 591,630 | 35.29 / 934.73µs | 0.39µs / 1.708ms | 0.950ms |
| 16ch × 12000 | 864,080 / 2,100,775 | 121.20µs / 3.493ms | 1.03µs / 5.654ms | 3.828ms |

WWB1 解码只创建 TypedArray 视图，不遍历全部数据；因此其耗时不是绘制成本。
Vitest 自动打印的“解码比 AC+测量快多少倍”比较了不同工作，不能作为优化收益。

### 60 秒并发长跑

每项都实际接收 840,070,000 B、记录 42,003,500 帧，主图+概览查询 1801 次。
接收 Lagged、评估队列丢帧、DataBus ingress 丢弃、预览 Lagged **均为 0**。

| 输入/图 | 实收 MB/s | 摄入 P99 / max ms | 组合查询 P99 / max ms | 评估队列峰值（帧） | 排空 ms |
|---|---:|---:|---:|---:|---:|
| 真实生成器，直接波形 | 14.0007 | 0.947 / 13.731 | 1.124 / 10.575 | 7000 | 12.51 |
| 真实生成器，四条 Math | 14.0003 | 2.585 / 4.246 | 4.135 / 6.131 | 17500 | 12.49 |

### 300 秒复测发现的失败

`soak-math-300s-native.log` 使用真实生成器、四条 Math、30Hz 主图/概览查询与
样本订阅。实收 4,200,070,000 B，平均 14.00017 MB/s，记录 210,003,500 帧。
约第 260 秒评估队列发生溢出，最终求值 **丢弃 10,500 帧**，因此本次不达标。
接收 Lagged、DataBus ingress 丢弃、预览 Lagged 均为零。

摄入 P99/max 为 3.071/10.467ms，组合查询 P99/max 为 4.390/6.956ms。
队列峰值 28,000 帧，排空 12.09ms。这些时间没有覆盖评估服务与调度等待，

本机 `/usr/bin/time -l` 测得最大 RSS 158,285,824 B（150.95 MiB），

评估队列现按每源 140,000 帧、8 MiB Vec 分配容量估计、256 批三项预算约束，
先达到任一预算就逐批丢最旧。单批本身超预算时拒绝整批并清空更旧积压，所有
未求值帧都计入缺口，原始记录不受影响。该预算在本场景提供约 200ms 的帧容量，
不是无限提高队列深度，也不是所有采样率下的固定延迟或进程内存上限。
诊断新增排队等待、blocking 调度等待、求值服务的生命周期最大墙钟耗时。
长跑现在强制检查 >10 MB/s、接收/求值/DataBus 摄入/预览零丢弃；任一失败退出非零。

### 同源合批的可重复停顿对照

## 验证边界与剩余风险

- 没有测量 Tauri IPC → WebView → Canvas/React 实际呈现的端到端延迟、掉帧和
  长任务；没有用真实桌面交互复现“全通道一起跳”。因此不能声称整软件已达标。
- 长跑查询按固定 30Hz 截止时间推进，停顿后可能连续补做查询；并不等同于
  真实显示流的自适应间隔，也没有覆盖 JavaScript 消费确认与 IPC 在途积压。
- 不覆盖物理串口、CAN 设备、网络拥塞、所有协议/schema、触发/FFT/导出同时工作。
  后端长跑使用生产路由和存储，但没有运行依赖 AppHandle 的完整 read_task 与 UI。
- 派生历史只有独立原始环，没有独立长期金字塔；tier 查询按块末时间取派生点，
  不是真正的派生 min-max 包络，且原始派生历史滚出后无法重建。
  原始概览的保留测试不能证明派生概览具有相同保证。
- 评估队列预算不含执行中批次、allocator 元数据或所有源的总和；多源/宽通道仍须独立测量。
  默认内存预算也不是所有源、派生列、原始字节、GUI 的进程级硬上限。
- 60/300 秒未出现退化不等于无限运行证明。Debug 与 Release 不可混用；
  压测时应记录构建模式、图结构、通道数、采样率、窗口和订阅数量。
